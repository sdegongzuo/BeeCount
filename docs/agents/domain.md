# Domain Docs

本仓库使用单一上下文的领域文档布局。工程技能在探索代码库前，可以按本文件约定读取领域文档和架构决策记录。

## 探索前优先读取

- 根目录的 `CONTEXT.md`
- 根目录的 `docs/adr/`

如果这些文件或目录不存在，直接静默继续，不要把缺失本身当成问题，也不要提前创建空文件。后续需要沉淀领域词汇或架构决策时，再由 `/domain-modeling`、`/grill-with-docs` 或 `/improve-codebase-architecture` 等技能按需创建。

## 文件结构

单一上下文仓库的推荐结构：

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-example-decision.md
└── src/
```

## 使用领域词汇

当输出内容需要命名领域概念时，例如 issue 标题、重构建议、调试假设、测试名称，应优先使用 `CONTEXT.md` 中定义的术语。

如果需要的概念还没有出现在领域词汇中，先判断是否是在引入项目并不使用的新词；如果确实是领域缺口，可以在后续 domain modeling 工作中补充。

## 标记 ADR 冲突

如果建议或实现会和已有 ADR 冲突，必须明确指出冲突点，而不是静默覆盖既有决策。

示例：

```text
与 ADR-0007（示例决策标题）冲突，但由于当前约束已经变化，建议重新评估。
```
